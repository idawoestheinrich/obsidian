###### The principle [Page 4](zotero://open-pdf/library/items/G9IHREUA?page=4&annotation=J478PIEM)
- Configure once, run anywhere [Page 4](zotero://open-pdf/library/items/G9IHREUA?page=4&annotation=8JMFJPVV)

###### Some key points [Page 12](zotero://open-pdf/library/items/G9IHREUA?page=12&annotation=XFY3ACHK)
- The environment the job runs in is completely detached from the one you  submit with [Page 12](zotero://open-pdf/library/items/G9IHREUA?page=12&annotation=QIWA9JXJ)
- Don’t put your ganga repository on a mass storage system [Page 12](zotero://open-pdf/library/items/G9IHREUA?page=12&annotation=3TUXJZ8R)
- We just about get away with AFS but definitely not EOS [Page 12](zotero://open-pdf/library/items/G9IHREUA?page=12&annotation=NB883ASQ)
- The monitoring is good - but not perfect [Page 12](zotero://open-pdf/library/items/G9IHREUA?page=12&annotation=HF9XVQ67)
- A lot of asynchronous I/O [Page 12](zotero://open-pdf/library/items/G9IHREUA?page=12&annotation=D9PQ6EU9)
- Made tricky on AFS by slowness of file system [Page 12](zotero://open-pdf/library/items/G9IHREUA?page=12&annotation=9MZALMMH)
- Can be memory hungry [Page 12](zotero://open-pdf/library/items/G9IHREUA?page=12&annotation=4W2VFZEP)
